# EasyReaktoro v0.15.1 检查与测试记录

日期：2026-09-14。Apple Silicon macOS，外部 Reaktoro 2.13.0。此次审查针对当前代码、真实求解及原生保存流程；下方保留旧版本检查记录作为历史，不将旧记录当作本次验证。

## 本次验证

411项前端、220项Python、18项Rust回归通过；最后一处兼容默认字段补强另跑8项Python回归通过。TypeScript、Vite及原生构建通过。Apple Silicon候选包的28项运行资源逐项核对与当前源码一致。

## 已复现并修复的问题

- UI 中温度为100°C，保留的代码单元仍是25°C时，运行采用了旧值，即使物料守恒也不能识别这个错误。现在图形模式采用当前UI参数，代码模式采用可见的参数赋值；自定义求解模块保留。旧loops/points与隐藏schedule、旧routes与迁移reaction_stages之间的优先关系也有独立回归。
- 批量生成某一方向时会丢失另一方向的变化；现保留线性和承接变化的另一方向。已有非均匀数列不会被另一方向的批量操作静默替换。
- 受流程覆盖的基础数量可能仍可修改却不起作用。现显示实际值和对应修改入口，仅当所有实际投料位置均被覆盖时锁定基础值。空基础量按实际来源、相态、species与份数判断是否需要；活动参数空值与负量仍不通过。
- 逐点条件表区分实际使用的来源与未取用来源，不把未生效的比例显示成实际输入。空草稿可跨历史、代码以及载入／另存设置保留；删除覆盖后重新指出具体缺量位置。
- 结果页整页缺失pH时可能静默把横轴改为压力；新结果打开失败时，迟到的旧结果可能覆盖当前选择。现保留用户所选指标，并以请求身份阻止迟到结果写回。
- 物料传递CSV不能作为平衡结果导入；导入时过滤运行坐标字段，按真实run identity匹配系统状态，不混合不同场景。
- 窄窗口下的物料选择、数量与移除按钮对齐；深色表单与滚动区域跟随主题。HKF未填写最高温度而序列化为0时，详情不显示“最高温度0K”。

## 实际求解与文件核对

1. 温度一致性：原生窗口运行100°C、1bar的水溶液，保存CSV与结果详情均为100°C，pH=6.128542428574593；独立Reaktoro求解为6.128542428574595，差1.78e-15。
2. 水相、固相和气相分开取用及复用的6点计算，与独立物料处理和Reaktoro求解逐species比较，最大差5.44e-14mol；单点及库存守恒残差约1.42e-14mol。
3. 缺填基础量：首点由参数投入0.2mol NaCl，后续两点继承前点；25、50、100°C各点Na均0.2mol。pH分别为6.9991390523860275、6.636974956933691、6.129290578403866；累计库存残差2.84e-14mol。保存重开后的基础量仍为空，不写成零。
4. 上述1点与6点真实输出，在内置NDJSON预览、CSV重新导入及独立HTML重开之间核对1404项species数值及T/P、pH、运行编号和坐标，数值一致，源文件未改动。

## 原生闭环与性能

最终0.15.1独立原生实例完成载入完整worker输出、Composition显示实际0.2mol、另存设置、运行3点和查看pH图。原输入SHA256保持不变；另存基础量为空值标记；原生summary全部字段与独立worker一致。1040×680浅深主题检查物料控件无横向溢出；实际结果窗口显示完整数据点和对齐的导航。
