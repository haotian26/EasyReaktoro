# EasyReaktoro 推送前对抗式审查

日期：2026-09-08（Australia/Melbourne）
审查版本：0.5.1 工作区及本地交付应用；外部 Reaktoro 2.13.0 / Python 3.12，Apple Silicon macOS。

**结论：主要功能已经达到可用 Beta 阶段，建议先修复下列 3 个已复现问题，再推送作为下一版公开源码。** 一个问题会绕过用户设定的计算适用范围，另外两个影响导入信息和结果分析状态。没有必要把动力学、固溶体或框架大版本升级塞进这一轮。

本轮没有修改功能源码或用户数据库，没有提交或推送。只新增本报告。反例使用临时夹具；当前用户数据库的检查为只读，其文件 SHA256 保持不变。

## 已复现问题

### 1. P1：原生物种的有效温压范围在模拟与 Python 读取器中被绕过

位置：`bridge/easyreaktoro_runtime/loader.py:30–44,74–82`；对照 `service.py:434–437`。

原生记录先进入 `objects`，`resolve()` 在第 44 行直接返回。因此，后面给标准态模型添加的 `valid_tp` 检查只覆盖非原生记录。数据库页面的单物种计算则单独检查该字段，造成同一数据库的两个计算入口行为不同。

复现使用 SUPCRT supcrtbl 的 H2O(aq)、H+、OH-，复制到临时 RTDB；将水的有效温度设为 290–310 K：

1. 数据库页面对应的 Evaluate 调用，在 373.15 K、1,000,000 Pa 被拒绝。
2. 同一 RTDB 建立单点模拟，1 kg 水、理想水相、100 °C、10 bar，关闭矿物渐进初始化。
3. 模拟成功完成一个点，未报告超出范围。

| 检查 | 实际结果 |
| --- | --- |
| 数据库 Evaluate | 拒绝，诊断含 T=373.15 |
| 模拟完成点数 | 1 |
| 模拟温度 | 100 °C |
| pH | 6.126250789886914 |
| 最大组分残差 | 0 mol |

守恒与收敛均通过，仍不能使越界计算满足用户设定的适用范围。问题适用于带显式范围的原生记录；没有据此断言现有所有模拟结果错误。

建议：统一读取器中所有模型类型执行相同范围检查，并覆盖依赖物种；模拟预检列出哪个物种、哪个点/循环越界。补充原生/转换记录、温度/压力、直接/间接依赖以及循环变化的交叉回归。

### 2. P2：导入复用会遗漏有效范围和文献差异

位置：`bridge/easyreaktoro_runtime/service.py:650–675`，尤其是第 653 行。

导入去重签名比较名称、组成、标准态模型、反应、活度参数等，却不比较 `valid_tp`、文献和备注。只要被比较字段相同，待导入记录就不会进入可选择的列表。

实际复现：已有 H2O(aq) 未设范围；待导入的同名记录增加 290–310 K 范围和文献。两条记录的完整 fingerprint 不同，导入预览却返回：

- `import_count = 0`
- `reused_count = 1`
- `issues = []`
- 最终记录仍为 `valid_tp = {}`。

源文件没有被破坏，但待导入的适用范围与出处没有进入目标数据库，也没有差异提示。

建议：将影响计算的范围纳入冲突判断；文献、备注和来源至少显示差异，允许保留现有值、采用导入值或保留不同版本。不要未经选择便自动放宽/收紧范围，也不要随意拼接文献作为新的科学依据。

### 3. P2：刷新结果和切换大结果预览会丢失分析配置

位置：`src/SimulationResults.tsx:64,71–72`；`src/explorer-shell.ts:108–117`。

“刷新结果预览”先发送 `clear`，清掉模型与视图后才重新载入。同一次运行切换预览循环/点段时，`datasetKey` 改变，而适配层只在 key 完全相同时保留视图。

使用实际 Explorer 解析脚本与应用适配脚本，在 JSDOM 中驱动压缩数据和宿主消息。选择 pH 曲线、设置标题、书签和参考点后：

| 操作 | 已选 pH 曲线 | 自定义标题 | 书签、参考点 |
| --- | --- | --- | --- |
| 后台更新同一数据片 | 保留 | 保留 | 保留 |
| 点击刷新对应的 clear → load | 清空 | 清空 | 清空 |
| 同一运行切换预览循环 | 清空 | 清空 | 清空 |

影响的是未保存的分析配置；计算文件仍在保存目录。大结果每换一个循环都需要重新选曲线，会影响比较效率。本复现验证了消息与视图行为，未声称完成最大规模数据的实机压力测试。

建议：普通刷新与显式更换数据源分开。同一运行不同数据片保留字段、曲线样式和图表布局；参考点、书签通过稳定运行点标识重映射，当前片未包含时明确说明，不能直接沿用旧数组下标。

## 优化与更新顺序

建议本轮修复 3 个问题、补交叉回归、更新测试报告与版本后再推送。README 的“v0.4.0 已知限制”标题也应同步当前版本，避免文档状态混淆。

随后优先考虑：

1. 结果工作区未保存提醒或恢复，特别是退出、替换数据源、打开另一运行之前。计算数据已落盘，自定义图表仍需手动保存 HTML 工作区。
2. 更清楚的适用性与预检信息：具体物种、温压点/循环、缺少参数，减少到实际求解时才发现的问题。
3. 较大实际结果的端到端压力验收，再确定分页、导出峰值内存和交互响应上限。
4. 逐步拆分大型 AppV3 与结果脚本，配合行为测试维护；不建议在推送前做大规模架构迁移。

依赖并非全部最新。当前可兼容范围内的 Dialog 补丁为 2.7.3；上游日志主要涉及 Android/Gradle、文档与依赖更新，未提供必须为本次 macOS 推送立即升级的依据。[上游变更记录](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/dialog/CHANGELOG.md)

React、Vite、TypeScript、Vitest 等存在较新大版本；本轮没有发现要求同时迁移这些框架的证据，建议单独安排升级与兼容验证。

动力学、真实时间积分、对流弥散、固溶体、开放 pH/Eh/逸度约束、非水液相属于后续计算能力，应按研究需求增加。缺少这些能力不妨碍将定位清楚的平衡工作台发布为 Beta。

未验证范围：第二台机器、Intel/Windows、最大 2,000,000 条物种结果的实机压力、本地独立 HTML 在外部浏览器中的完整操作、Apple 公证及正式安装包分发。推送源码时可如实说明边界；面向其他用户提供安装包前应补相应验收。
